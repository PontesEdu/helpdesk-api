# 0009. GitHub Flow, Conventional Commits, sem atribuição ao Claude

**Status:** aceita.

**Decisão:**

- `main` sempre verde, branches curtas e PR próprio a partir da Fase 0. Git Flow dispensado.
- Conventional Commits, por ser convenção útil para o aprendizado, não por obrigação do mercado.
- CI com lint, typecheck, testes e build. Check obrigatório na `main`, sem exigir aprovação, já que há um único desenvolvedor.
- **Commits e PRs não citam Claude ou Anthropic.** Sem `Co-Authored-By` e sem "Generated with Claude Code", para que só o dono do repositório apareça como colaborador.
- Claude gerencia o fluxo com a CLI: cria a branch, faz commits pequenos, faz push e abre o PR, mostrando cada passo. O dono acompanha o PR antes do merge. Operações destrutivas exigem autorização explícita.
- Nome de branch por tipo: `feat/...`, `fix/...`, `chore/...`, `docs/...`.
- Repositório privado por enquanto, por decisão provisória; tornar público é decisão do dono.

**Fontes:** [Conventional Commits](https://www.conventionalcommits.org/en/v1.0.0/), [nota do autor do git-flow](https://nvie.com/posts/a-successful-git-branching-model/), [DORA](https://dora.dev/capabilities/trunk-based-development/), [tamanho de mudança no Google](https://google.github.io/eng-practices/review/developer/small-cls.html).
